Rentiva 6.3.0 — A site-wide rental deposit, safe editor previews, e-mail settings that apply, and a booking form the server checks

October 24, 2026 · 9 min read
MaxHandMade
Maintainer

6.3.0 gathers the work since 6.2.1. Rentals get a site-wide deposit setting, a vehicle set to transfer only can no longer be rented, and Rentiva widgets show safe previews in the Elementor and block editors. E-mail settings that were saved but ignored now apply, and the booking form checks on the server what it used to take from the browser. No database step runs on update. 6.3.1 followed the same day with a fix for Elementor sites — see the end of this post. It is published on WordPress.org, so WordPress offers it to you as an ordinary update. Using Rentiva Pro? Update Pro to 6.4.0 right after.

A site-wide rental deposit​

Settings > Payment has two new fields: Rental Payment Type (full payment or percentage deposit, default percentage) and Deposit Rate (%) (1–100, default 10). The defaults keep today's behaviour. The Payment tab is now always shown; it used to appear only without WooCommerce. Every price screen reads the same rate.

  • A vehicle's own deposit rate still wins over the site-wide setting.
  • An empty deposit field now follows the site-wide setting. It no longer means a fixed 10%, and the booking form no longer charges in full because of it.
  • The vehicle field accepts 1–100 (it was capped at 50), and the edit screen names the site-wide value it falls back to.

Transfer-only vehicles can no longer be rented​

A vehicle whose service type is "transfer only" no longer appears in the vehicle grid and list, search results, featured vehicles, the booking form, alternatives, the calendar's vehicle switcher or the manual booking list, and its page has no booking button. The server refuses a rental booking, quote or payment for it. Transfer bookings for that vehicle are not affected, and a vehicle with no service type stays rentable.

Safe previews in Elementor and the block editor​

  • Rentiva widgets render inside a preview frame. Account widgets (My bookings, Favourites, Payment history, Vehicle comparison, User dashboard) always show sample rows with a "Preview: sample data" note — never your own account data. Vehicle details and the rating form show a sample vehicle when the page has none, and a clear note when the vehicle ID is wrong. Catalog widgets show your real public data. Forms in the editor are inert.
  • One "Rentiva" category. All Rentiva blocks sit in a "Rentiva" category in the block inserter, and the Elementor widget category is renamed "Rentiva"; saved pages are not affected. The "MHM " prefix was removed from widget and block names.
  • Elementor's "Parity Controls" section is now "Additional Settings", with translatable labels and options. Saved widget settings are unchanged.
  • Block settings panels are translated. If a WordPress.org language pack is installed, its newer translations win, and strings the pack does not have yet come from the plugin's own translations instead of showing in English.

E-mail settings that were ignored now apply​

  • A template is sent only while its "Enabled" box is ticked. A template that was never saved counts as enabled, as the screen shows it. Previews and test sends ignore the box. The global booking and welcome e-mail switches now match the templates they name; before, they matched none.
  • One cancellation e-mail. When a booking is cancelled, the customer gets the "Booking Cancelled" template (or the automatic-cancellation template when that one applies) instead of the generic status e-mail plus a second cancellation e-mail. If that template is disabled, nothing is sent. It now follows "Enable Outgoing Emails" and test mode like every other e-mail. The admin copy and admin alerts still go out, in test mode to the test address.
  • The "Admin Email" fields are used. Booking alerts go to the address under Booking Notifications, refund alerts to the one under Refund Emails. An empty or invalid field still falls back to the site admin e-mail. Admin alerts that were sent directly now also respect test mode.
  • Customer e-mails use the site language, even when the admin who triggers them uses another profile language.
  • The "Booking Cancelled" e-mail's enabled box, subject and body are now saved, and the e-mail preview lists every template by its translated name and fills it with sample data.
  • Booking e-mails show one booking number in the subject and the body (the order number when there is one), and the cancellation e-mail's account button opens the booking.

Bookings the server checks​

  • The booking form checks on the server what the browser sends for the return time, required add-ons and the payment type. The return time is set to the pickup time on the server, so the priced period is the one blocked. Required add-ons are enforced and shown checked and locked. Only "deposit" or "full" is accepted as the payment type.
  • Saving a booking in the admin uses the booking form's calculation. It no longer drops add-ons from the total, charges a fixed 20% deposit, ignores the weekend rate, or re-prices transfer bookings at the vehicle's daily rate.
  • Editing a booking in the admin checks availability. Moving a booking onto taken dates, or re-confirming a cancelled booking whose dates were sold, is refused with a notice. A moved booking frees its old dates and holds its new ones.
  • When the chosen vehicle is not free, the booking form shows the notice and suggested alternatives, and the booking button stays disabled until an available vehicle or dates are chosen.

What to check after updating​

  • Vehicle deposit fields: a vehicle with an empty field now follows the site-wide rate under Settings > Payment; one with its own rate keeps it.
  • E-mail templates: a template whose "Enabled" box is unticked is no longer sent. Look over the boxes on the e-mail settings screen.
  • "Admin Email" fields under Booking Notifications and Refund Emails: they are now used, so make sure they hold the right address.
  • Drop-off location in the search form: it is hidden by default now; it only mirrored the pick-up location and nothing used it. Add show_dropoff_location="true" to the shortcode, block or Elementor widget to show it.
  • Transfer-only vehicles disappear from rental listings and the booking form.

Smaller things you will notice​

  • The customer's booking page matches the booking. Pending, cancelled and completed bookings get their own heading; the deposit shows as paid only after the payment arrives; "Pay Remaining Amount" waits for the deposit; pickup instructions appear only for confirmed bookings. The booking number is the same in the list, the dashboard and the detail, and it can be searched.
  • Cart and order: each booking shows as the vehicle's name plus "rental" with the vehicle's image, each add-on is listed once with its price, transfers have no return-date row, and order dates use the site's date format. Booking form prices follow the store's currency position and thousand separator.
  • Vehicle pages: the rating summary shows a bar for every star value (1 and 2 stars were missing); "Similar vehicles" is hidden when empty and no longer lists the vehicle itself; visitors no longer see raw [rentiva_login_form] text under reviews, and Register appears only when the site allows registration.
  • Vehicle comparison shows default rows until you choose your own, and your first selection is saved. "Reset to defaults" on the Display tab restores the default fields instead of hiding them.
  • Availability calendar: picking the same day for pickup and return opens the booking form with the pickup date filled instead of an error. Two calendars on one page no longer drive each other, and the vehicle dropdown works again.
  • Settings that now stick: the default rental location on the Vehicle tab is saved, search uses its minimum rental days, the contact form uses the support e-mail from the General tab, and the e-mail header image field is visible.
  • Translations: the Turkish translation was reviewed end to end, Turkish sites write percentages as "%20", and admin screens no longer show recently added strings in English when a WordPress.org language pack is installed.

Security​

Besides the booking form checks above: a vehicle title with an apostrophe no longer breaks the calendar's "Choose another vehicle" button, vehicle data in the availability calendar and the booking edit screen is always handled as text, and the lazy loader no longer loads remote content or scripts from data-lazy attributes.

For developers​

New filters: mhmrentiva_cart_item_name, mhmrentiva_email_template_labels, mhmrentiva_email_preview_context, mhmrentiva_parity_labels, mhmrentiva_translation_dirs, mhmrentiva_render_context and mhmrentiva_settings_programmatic_keys. Add-ons can rely on DepositCalculator::resolve_rate(), VehicleDataHelper::get_service_type() / allows_service() / service_meta_query(), RenderContext, BlockRegistry::register_block() and CurrencyHelper::format_percentage() from 6.3.0. Util::has_overlap_locked() takes an optional booking to exclude. The content and script types of the data-lazy loader were removed, as was the unused mhmrentiva_booking_validation hook-up.

6.3.1 follow-up​

6.3.1 followed on the same day with two fixes:

  • Elementor-built pages are found. A Rentiva widget, or a [rentiva_*] shortcode inside an Elementor widget, lives in Elementor's data rather than the page content, so Rentiva's page finder missed it: "Book now" buttons and other links fell back to the home page, and Shortcode Pages listed the page as missing. A page with the shortcode or block in its content still wins. On Elementor sites whose vehicle-details page is now found, vehicle pages move under that page, with a 301 redirect from /vehicle/..., as on block and shortcode sites.
  • Translation tokens in notices now use a format WordPress.org's translation tool can check, and the Turkish catalogue uses the plural formula translate.wordpress.org uses.

Where to get it. Rentiva is on WordPress.org and on GitHub as v6.3.0; both carry the same files. WordPress.org holds new versions for a few hours before sites are offered the update. Using Rentiva Pro? Update Rentiva first, then Pro to 6.4.0. The full changelog in both languages ships with the plugin.
